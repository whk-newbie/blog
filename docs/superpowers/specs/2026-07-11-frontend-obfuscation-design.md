# Frontend Obfuscation Design

## Goal

Increase the cost of reading the application's business JavaScript without
breaking Vite's lazy-loaded Vue routes in production.

## Root Cause

The original production configuration registered `rollup-plugin-obfuscator` in
Vite's plugin chain. That plugin transforms source modules before Vite finishes
analyzing dynamic imports. Consequently, imports such as
`import('@/components/layout/AdminLayout.vue')` can remain unresolved in the
browser bundle. Browsers do not know the Vite-only `@` alias, so navigating to
lazy routes fails.

## Design

1. Keep Vite and Terser responsible for the normal production build:
   no source maps, console/debugger removal, and identifier mangling remain
   enabled.
2. Remove source-stage obfuscation from the Vite plugin chain.
3. Add a post-build obfuscation step that runs only after Vite has emitted
   hashed chunks. It must never process the Vite entry/router chunk, preload
   runtime, or third-party chunks.
4. Obfuscate application feature chunks only. The implementation must preserve
   module specifiers and Vite preload metadata exactly.
5. Fail the build if generated JavaScript contains a dynamic import using the
   `@/` alias.

## Safety Boundaries

- No secret, authorization rule, or trust decision may rely on obfuscation.
  Backend authorization remains authoritative.
- The router entry and Vite runtime are deliberately excluded because they
  contain lazy-import dispatch and preload bookkeeping.
- Third-party chunks are excluded: they add size and compatibility risk without
  protecting application logic.
- The existing `dist` directory is regenerated by the production build; source
  files are not rewritten by the obfuscation step.

## Verification

1. Run the production build.
2. Scan emitted JavaScript for `import('@/` and fail if any occurrence exists.
3. Run a production preview and navigate to the public timeline and the admin
   route. Their lazy-loaded chunks must load without module-specifier errors.
4. Confirm the selected business chunks contain the expected obfuscation output
   while the router entry retains Vite's relative hashed imports.

## Non-Goals

- Obfuscating vendor libraries or the Vite runtime.
- Treating obfuscation as a security boundary.
- Changing API authentication or authorization behavior.
